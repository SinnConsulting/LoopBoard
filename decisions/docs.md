# Decisions — Docs, conventions & compression

One line each: what, why. Newest at the bottom. Index: [../DECISIONS.md](../DECISIONS.md).

- Renamed the extension "Claude TODO Board" → **LoopBoard** (t-8823): display name "LoopBoard", package/publisher `loopboard`, id prefix `loopBoard.*` (keeps the camelCase convention). Clean break on `claudeTodo.*` settings keys (no aliases — unpublished at 0.1.x, README migration note instead). Terminal names stay "Claude <Model>" (they host the actual claude CLI). Stale `claude-todo-board-vscode-extension/` duplicate deleted.
- Compression of `media/template-loop.md` is a maintainer-only, propose-only skill, not a two-file raw/processed split (t-b716): `.claude/skills/template-loop-compress/SKILL.md` reads the file and proposes a token-reduced, meaning-preserving candidate for human review — it never writes `media/template-loop.md` itself, because the file's marked sections are pushed by `src/sync.ts` into every user's live `.loopboard/LOOP.md`, making an unattended rewrite an unattended edit of other people's agent instructions. Scoping is a `.claude/rules/template-loop-compress.md` rule with a `paths:` frontmatter array (not a settings.json hook, not skill-description matching alone) — the pattern is repo-local under `.claude/**`, already excluded from the `.vsix`. An earlier re-groom of the task briefly committed to a `template-loop.raw.md` + generated `template-loop.md` two-file layout reading one answer too literally; the human's direct follow-up answer ("stick with just one file") settled it back to the single-file design.
- `template-loop-compress` re-scoped: caveman-full-tier terseness, always-Opus subagent, self-check-gated write + PR (t-b716, follow-up): three of the task's own earlier settled decisions were reversed with the human's direct sign-off this session. (a) The compression technique moved from "redundancy removal only, grammatical English, no telegraphic prose" to the `caveman` skill's "full" intensity tier — drop articles/filler/pleasantries/hedging, fragments OK, short synonyms OK, standard tech acronyms OK, never invent abbreviations (`cfg`/`impl`/`fn` tokenize the same as the full word: zero saved, less clear), no causal arrows, no decorative tables/emoji — layered UNDER the pre-existing five-item untouchable list (sync markers, `## Automation` heading + first fenced block, Rule numbering 1–17, the task-index/task-file format blocks, every normative clause/count/path/filename) plus byte-identical fences/inline code/URLs, which stay exactly as strict as before and always win on conflict; caveman is a technique adaptation, not a vendored dependency (no code or script from `caveman` or `caveman-compress` is used). (b) The skill now always delegates the compression to a subagent with `model: opus` regardless of which model's loop triggered it, mirroring `.loopboard/LOOP.md` Rule 14's groomer-subagent routing, instead of running inline. (c) The "propose-only, never write the file" gate was replaced by a self-check-gated write + PR: on a passing self-check the skill writes `media/template-loop.md` on a branch off `main` and opens a PR with no chat-level approval, because LOOP.md Rule 7's mandatory-PR review is already the repo's review point for every other change; on a failing self-check it still writes nothing and reports. The propagation risk that motivated propose-only (marked sections pushed into every user's live `.loopboard/LOOP.md` by `syncTemplates`/`autoHeal`) is unchanged and is now the stated reason the self-check + PR discipline is non-negotiable.
- Workspace custom loop rules live in a `loopboard:custom` block inside `.loopboard/LOOP.md`, not a separate `LOOP-optional.md` (t-4a04): workers already re-read LOOP.md every pass, so text placed there is delivered live with no terminal recycle, whereas a separate file would only ever be opened if the sync-managed Automation block told workers to — a `media/template-loop.md` edit plus a Sync in every workspace. The `custom:` namespace (not `sync:`) makes "Sync never overwrites it" true by construction rather than by convention: `sync.ts`'s scanner matches only the literal `loopboard:sync:` segment and only rewrites blocks whose id it matched from the TEMPLATE, so the custom block is invisible to it; the one contact point, the new-section insertion path, splices adjacent to a neighbour and never over it. The reconciler additionally refuses a LOOP.md with no `loopboard:sync:` markers, so a custom block can never come to exist in a file that `syncTemplates`' legacy full-replace path would later overwrite.
- Custom rules are reconciled by PER-LINE provenance, not block ownership (t-4a04): every extension-written line ends in `<!-- loopboard:custom-rule:<fnv1a-of-normalized-text> -->`, and each pass classifies the block's list items four ways — unmarked = hand-owned (untouched); marked but the id no longer hashes to the line's own text = the human edited it, so it is ADOPTED (marker stripped, text kept, never deleted); marked and still in the setting = kept; marked and absent from the setting = deleted. Missing rules are then appended in setting order and the list renumbered contiguously. This is the only model that satisfies both "removing an entry removes its line" and "a hand-written line is never destroyed"; union/append cannot honour removal, seed-once kills live reconfiguration, and a setting-owned block destroys hand edits. In-text markers beat a `workspaceState` ledger because `.loopboard/` markdown is the git-tracked source of truth while a ledger is per-machine — a fresh clone would prune nothing and duplicate everything. Accepted costs: a hand-reworded line yields a near-duplicate pair, rewording in Settings is delete+append (the rule moves to the end), and positional numbers can stale out prose references.
- Custom Rules are numbered in their own namespace and WIN over a predefined Rule they contradict (t-4a04): "Custom Rule N" vs "Rule N" are separately addressable, so Rules 1-17 keep their numbering for `README.md`, ~15 code comments, `CLAUDE.md` and the compress skill's "Rule numbering 1-17" self-check. Precedence is a sentence in the rendered lead-in and nothing more — the extension never detects, validates, reports or annotates a contradiction, `## Rules` stays byte-identical, and there is deliberately no carve-out for the human-gate Rules 1/2, since a carve-out would need machine enforcement this feature does not have. The motivating case is a workspace re-tightening the Rule 7 that t-4b97 relaxes upstream.
- Rule 7 relaxed: branch mandatory, PR only on explicit request (t-4b97). The rule is REWRITTEN IN PLACE, never deleted — deleting it would renumber Rules 8–17 and break `README.md:138`, the compress skill's "Rules 1–17" self-check (`.claude/skills/template-loop-compress/SKILL.md`), and the ~15 rule-number comments across `src/**`/`media/**`. Rule 7 now says: never commit to `main`, all work on a `task/**` branch off latest `main`, a PR is optional (open one only when the user asked for it), and before `phase: review` the task file's `link:` records the delivery — the PR URL when a PR exists, otherwise the `task/**` branch name, never a commit sha, and never empty. Rule 12 relaxed in step, or it would have independently cancelled the change: it now requires only that every change is committed and pushed to its branch before the session ends, with the "ends in a PR (draft PR if unfinished)" clause removed outright. Rule 9's "open the PR from there" tail and the `## Automation` fenced block's "When finished, open a PR (Rule 7)" sentence were rewritten too — the fenced block is the literal standing prompt every loop re-reads, so leaving it alone would have kept workers opening PRs regardless of the Rules block. The `link:` grammar widened to `<url or task/** branch name>`, matching what `src/taskfile.ts` already accepts (free comma-separated text, no URL validation) and what `src/gates.ts` already tolerates (the accept gate never inspects `links`). Accepted consequence: a branch-name `link:` renders a board chip that does nothing on click (`src/controller.ts` opens a link only if it starts with `.loopboard/` or parses as a URI with a scheme) — making it clickable is a separate task. No `src/**` change was needed: nothing in code, and nothing in CI, ever enforced the PR (`build.yml` triggers on push to `task/**` and comments the artifact link on a PR only "if any"). The `template-loop-compress` skill's mandatory write+PR gate became a soft, pre-commit-style step: the self-check stays a HARD gate on the skill's own write, but delivery follows the new Rule 7. Its propagation risk is restated rather than dropped — marked sections are pushed into every workspace's live `.loopboard/LOOP.md`, so with the PR optional the self-check is the only automated gate before the branch and human review shifts to branch review/merge.
- CLAUDE.md gets its own compress skill + rule pair rather than a generalized compressor (t-cmp1). `CLAUDE.md` loads into every Claude Code session in this repo before any work starts, so its length is a fixed per-conversation token cost, and it grows by default — every landed feature appends to Critical learnings and Conventions, and until now there was no compression route for it at all. The sibling `template-loop-compress` was NOT generalized to take a target file: its "never engages for any other file" guarantee is what makes it auditable, so `.claude/skills/claude-md-compress/` + `.claude/rules/claude-md-compress.md` mirror it as a second single-file pair, each with its own tight untouchable list (here: every `@`-include line — a reworded include silently unloads a whole ruleset with no error — the Non-negotiable numbering, the Commands fence, every "Rule N" cross-reference into LOOP.md's numbering, and every normative clause/count/path/identifier). The contract is strictly LOSSLESS: deleting content that has gone obsolete stays a separate human-reviewed edit, and the skill is told to report suspected staleness rather than act on it. Enforcement is both routes, as for t-1cc8: on-request compression through the skill (Opus subagent, self-check hard-gating its own write) plus `test/claude-md-budget.test.js` under `make check` — the mechanical half, because CI cannot see doc-only pushes (`build.yml` has `paths-ignore: ['**/*.md']`) and a delegated implementer subagent cannot invoke a skill unless one is explicitly handed to it. Budget = 173 lines = the compressed 157-line baseline plus ~10%. Honest limit recorded in the test: the baseline pass yielded only 155 → 154 lines because the file is dominated by inline code spans, literal paths and normative clauses that the untouchable list forbids touching — the prose slack is spent, so a future overrun cannot be answered by another compression pass, only by a human-reviewed obsolescence deletion or a deliberate budget raise.
- LOOP.md's length is enforced by a line budget in the test suite, not by the compress skill alone (t-1cc8). `media/template-loop.md` is re-read by every loop worker on every pass and pushed into every workspace's live `.loopboard/LOOP.md` by `syncMarkedSections` (`src/sync.ts`), so its length is a per-pass token cost multiplied across all running loops — and it only ever grew, because the `template-loop-compress` skill engages ONLY when explicitly asked and `.claude/rules/template-loop-compress.md` fired on every touch of the file while demanding nothing of an ordinary feature edit. Enforcement is now both halves (human decision): the rule gained an on-touch mandate — any change that grows the file strips an equivalent amount of no-longer-needed prose in the same change or runs a compression pass first — and `test/template-budget.test.js` asserts a hard maximum line count under `make test`/`make check`. The test is the load-bearing half: CI cannot cover this (`build.yml` carries `paths-ignore: ['**/*.md']`, so doc-only pushes produce no build) and skill/rule enforcement does NOT bind a delegated implementer subagent, which cannot invoke a skill unless one is explicitly handed to it — what reaches such an agent is the mechanical `make check` gate. Budget = LINES (dependency-free, stable across editors, readable in the failure message), set at 228 = the compressed 2026-08-28 baseline of 207 plus ~10% headroom, so a clause can be added without ceremony while sustained growth cannot pass unnoticed; raising it requires a deliberate edit to the test. The baseline itself landed in this same change through the skill's own gated flow (213 → 207 lines, self-check green: six sync markers intact and ordered, the `## Automation` fence byte-identical, Rules still numbered 1–17, all 109 inline code spans byte-identical). Scope is LOOP.md/the template only — CLAUDE.md compression is deferred to its own story (t-cmp1).
- `DECISIONS.md` split into topical `decisions/` category files (t-9cd6): every task branch appended to the same trailing hunk, so any two concurrent PRs conflicted on it; with six topic files concurrent branches usually touch different files. Entries migrated verbatim, `DECISIONS.md` kept as a pointer/index so stale references don't 404; residual same-category conflicts stay possible but rare (`.gitattributes` `merge=union` per hot file remains an available add-on, deliberately not applied). `VERIFICATION.md` intentionally untouched — its numbering is positional and must keep conflicting loudly.
