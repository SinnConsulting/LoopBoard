# Decisions

One line each: what, why.

- Extension lives at repo root (package.json/src/media/test here), not a nested `loopboard/` dir — the workspace this operates on IS this repo, so `workspaceContains:TODO.md` activation and workspace-root file IO line up.
- Tests are plain CommonJS `.js` under `test/`, requiring compiled modules from `out-test/` — keeps devDependencies to `typescript` + `@types/vscode` only (no `@types/node`), per the non-negotiable.
- `tsconfig.test.json` compiles only the pure modules (parser/writer/model/merge) with `types: []` so they never depend on node/vscode typings; the vscode-touching modules are built by the main `tsconfig.json` into `out/`.
- Board carries structural `phaseHeadings` + `sectionExtras` (attached as non-enumerable-ish props via helpers `getPhaseHeadings`/`getSectionExtras`) so exact section headings and HTML-comment templates round-trip verbatim without bloating the documented `Board` interface.
- Parser strips leading `❓`/`⚠️` from question/feedback text and the writer re-adds them — canonicalizes emoji placement so a file missing them normalizes cleanly.
- `make test` runs `node --test 'test/*.test.js'` (glob, not a bare dir) because Node 22 treats a bare `test/` argument as a module path.
- Pure field-patch + conflict logic lives in `merge.ts` (no vscode) so the merge protocol is unit-tested in Docker; `store.ts` will consume it.
- Ported the design bundle's mockup (`loopboard-vscode-extension/project/board.dc.html`, `sidebar.dc.html`) — a React-like DC prototype — into vanilla `media/*.{html,css,js}`: same regions, type scale (15/13/11), 4px grid, colors via `var(--vscode-*)`, and the two allowed animations (attention pulse, refresh flash) with `prefers-reduced-motion` honored.
- Main `tsconfig.json` adds the `DOM` lib (not `@types/node`) to get `setTimeout`/`TextDecoder`/`TextEncoder` in the extension host without violating the "typescript + @types/vscode only" devDependency rule.
- Writing review `feedback:` from the board is a **field patch**, not a phase move — the board only performs the two human gates (New→Backlog, Review→Done); the loop moves a Review task back to In Progress on its next pass per Rule 13. The mockup's optimistic auto-move was prototype-only.
- Pure gate transforms (`gates.ts`) and the pure loop-command builder (`loop.ts`) are split out of `store.ts`/`terminals.ts` (which import vscode) so both are unit-tested in Docker.
- Webview normalizes the model select's `default (opus)` display value to `''` before sending a patch, matching the store's "no model" representation so an unchanged/default model never trips a false same-field conflict.
- Board full-re-renders on each refresh but **defers** applying an incoming board while a field is focused (`pendingBoard`, flushed on `focusout`) so a loop write mid-typing can't discard the user's in-progress input.
- Added `.vscodeignore` so the packaged `.vsix` ships only `out/` + `media/` + manifest/README (26 files) — source, tests, docs, and the design bundle are excluded.
- Board content pane is left-aligned against the rail (`.pane-inner` margin 0, not auto-centered) — on wide windows the mockup's centered column left a huge gap after the rail, making the cards look like a detached second menu.
- Board's left rail removed (it duplicated the sidebar): phases are horizontal tabs in a top bar with the New-story button, cards take the full remaining width; loop controls live only in the sidebar and gained a stop (■) button (`stopLoop` → `TerminalManager.stop()` = dispose without respawn).
- Textareas auto-grow after mount via `requestAnimationFrame` in `render()` — `scrollHeight` is 0 on detached nodes, so growing at build time left multi-line descriptions cropped at 2 rows.
- New tasks are approved with an explicit ✓ Approve button instead of a bare checkbox (same `promote` gate); Review keeps the checkbox + confirm since accepting rewrites two files.
- `loopBoard.autoRecycle` defaults to **off** (user preference): auto-disposing a model's terminal when its task leaves In Progress kills the session mid-flow more often than it helps; ♻ is the manual, deliberate restart.
- Loop start passes the /loop prompt as the claude CLI's initial prompt argument (`claude --model X --permission-mode Y '<prompt>'`, single-quoted with `'\\''` escaping) instead of injecting the prompt text into the running TUI — injecting the multi-line prompt via sendText/sendSequence was unfixably flaky (bracketed paste swallows the newline; Enters within the TUI's paste-detection window get folded into the paste; sendSequence races terminal focus). The arg approach reliably delivers the prompt as argv, but the CLI only *seeds* it into the REPL input (a pasted-text chip) — it does NOT auto-submit. So after launch we send one standalone Enter (`terminal.sendText('', true)`) after `SUBMIT_DELAY_MS` (3.5s), once the CLI has booted and its paste-detection window has closed; a lone Enter after that window is not folded into the paste. `loopBoard.startupDelayMs` stays removed (the delay is now a fixed internal constant, not the old inject-the-prompt delay); ♻ restart re-arms the loop automatically.
- Fresh workspaces get a "Create TODO.md & DONE.md" button (sidebar + board empty state): the initial tracker ships as `media/todo-template.md` (test-pinned: parses empty, fixpoint, `{MODEL}` block present); `Store.createInitialFiles` never overwrites existing files. Works pre-TODO.md because contributed views activate the extension implicitly (`onView`).
- Renamed the extension "Claude TODO Board" → **LoopBoard** (t-8823): display name "LoopBoard", package/publisher `loopboard`, id prefix `loopBoard.*` (keeps the camelCase convention). Clean break on `claudeTodo.*` settings keys (no aliases — unpublished at 0.1.x, README migration note instead). Terminal names stay "Claude <Model>" (they host the actual claude CLI). Stale `claude-todo-board-vscode-extension/` duplicate deleted.
- Release pipeline (t-9c4e) ports ClockClock's semantic-release setup: `.releaserc.json` with the commit-analyzer/release-notes-generator/github plugin trio, `release.yml` with a `release` job (cycjimmy/semantic-release-action@v4, GITHUB_TOKEN) and a gated `vsix` job that builds (npm ci + tsc + node --test on Node 22 — CI runners aren't the host, so the Docker-only rule doesn't apply) and packages with `vsce package <version> --no-dependencies --no-git-tag-version --no-update-package-json` — version is injected into the vsix manifest only; package.json's version stays frozen in git (no bot bump commits). Artifact goes to the GitHub Release via `gh release upload`; Marketplace publish deliberately deferred (t-a37f follow-up). `environment: All` omitted (ClockClock-specific). `.github/**` + `.releaserc.json` added to `.vscodeignore` (they leaked into the vsix, 30→32 files).
- Loop terminals get a tiny bootstrap paste, not the full prompt (t-1d91): `buildLoopCommand` now emits `/loop <interval> You are running as model <model>. Open TODO.md, read the loop worker instructions in its ## Automation section, and follow them exactly...` — the Automation fenced block holds the standing model-agnostic instructions, so editing TODO.md retunes running loops on their next pass (only the interval is fixed at spawn). Chosen over startup validation (shell-integration exit-code checks only catch fast failures; tmux stays the v2 path — user decision: no follow-up story). Review feedback reversed the delivery mechanism to the ONE-command argv form (`claude --permission-mode <mode> --model <model> '/loop ...'` + lone Enter after boot to submit the seeded chip): with the bootstrap prompt this short, the quoting hazards that killed the argv approach for the 3,000-char prompt no longer apply.
- v2.0.0 storage split (REFACTORING.md): `TODO.md`/`LOOP.md`/`DONE.md`/`tasks/<id>.md` all live under `.loopboard/`; breaking, no migration. The slim index (`TODO.md`, grammar v4) carries only id/phase/model/groomer/questions per entry — every removed key (owner/dates/worklog/link/depends on/description/note/feedback/DELIVERED) becomes an `unknownLines` entry (preserved + flagged), except `completed:` which is canonical in `DONE.md` only (parser gets an `allowCompleted` flag). Detail lives in `tasks/<id>.md`.
- Model split into `IndexEntry` (index file) + `TaskDetail` (task file) + composed `Task = IndexEntry & TaskDetail & { hasDetailFile }` (view/webview shape stays stable); `Board` drops `automation` (loop instructions moved to LOOP.md) and its `done` is now `IndexEntry[]`. Parser returns an `IndexDoc { preamble, entries }`.
- Task-file format (`taskfile.ts`, pure) has no frontmatter — the index owns title/phase/model/groomer/questions; the writer rewrites the H1 from the index title on every save and emits fixed heading order (Meta/Description/Notes/Worklog/Feedback/Delivered), omitting empty sections; unknown headings/keys round-trip verbatim at the end (keeps the fixpoint idempotent). `## Notes` is a bullet list → `notes: string[]`.
- Field patches route by destination file (`merge.patchTarget`): index fields (title/model/groomer/answer) patch `TODO.md`; detail fields (description/note/feedback) patch `tasks/<id>.md` via `applyDetailPatch`; both keep the disk-wins conflict rule. The board's note textarea edits the whole `## Notes` section as one newline-joined value (split on save, empties dropped) — owner/dates/links/depends-on stay loop-written only.
- Gates stay pure by mutating the in-memory `IndexEntry`/`TaskDetail` they're handed; the store orchestrates the per-file writes. Promote = index patch (phase→backlog, uncheck) then detail patch (`promoted:` + worklog). Accept = detail patch (`completed:` + worklog) → **write DONE.md first**, then remove the index entry, so a crash between them leaves a visible duplicate rather than a lost task; the task file stays in `tasks/`. Delete = drop the index entry AND `tasks/<id>.md` (unaccepted tasks only). Loop command builder (`loop.ts`) now takes `store.loopText` and slices the `## Automation` section before matching a fence — LOOP.md has several earlier fences, so the old first-fence regex would pick the wrong block.
- Init: `loopboard.init` (command) and the board empty-state button share `Controller.onCreateFiles`, which reads `media/template-todo.md` + `media/template-loop.md` and calls `store.createInitialFiles` — scaffolds `.loopboard/TODO.md` + `LOOP.md` + empty `tasks/`, no DONE.md (lazy), refuses (returns false, warns) if `.loopboard/` already exists. Activation moved to `workspaceContains:.loopboard/TODO.md`; a root `TODO.md` is ignored. `REFACTORING.md` added to `.vscodeignore` (it leaked into the vsix at 33 files → back to 32).
- Marketplace publish is automated as the LAST step of release.yml's `vsix` job (`vsce publish --packagePath` with the repo-level VSCE_PAT) rather than a `release`-event workflow — GITHUB_TOKEN-created releases don't trigger other workflows. It runs after the asset upload and version-bump commit so a Marketplace flake can't block them; `publish.yml` (workflow_dispatch) stays as the manual retry path.
- New Story drafts always carry explicit `groomer:` + `model:` in the index: `Controller.onMessage('createDraft')` resolves an empty composer selection to the configured `defaultModel` (opus) so an ungroomed draft is never left to the implicit "no field = default" routing — a loop can tell unambiguously who grooms and who works it; a non-default pick lands verbatim. Grammar keys stay `groomer`/`model` (unchanged); only the composer UI relabels the worker selector "Model" → "Work with" (groomer stays "Groom with").
- Models are configurable (t-c1a7, absorbed t-e4d2): the LOGICAL slot set stays fixed — `opus`/`sonnet`/`fable` plus new **`haiku`** — sourced from one place (`model.ts` `BUILTIN_MODELS`/`BUILTIN_MODEL_IDS`, which `parser.ts`/`merge.ts`/`terminals.ts` import so the allowlists can't drift). What each slot spawns as `claude --model <string>` is resolved from the `loopBoard.models` setting: per slot, `enabled` (false hides it from the Loops overview + board selects) and `model` (a custom `--model` string that REPLACES the default when non-empty — this is how you get `opus[1m]` for the 1M window, or an org alias). Chosen REPLACE-per-slot over a free-form user-defined list (user decision) — keeps `Model` a 4-value union and TODO.md `model:`/`groomer:` values a closed set, so no parser widening. Security: every resolved `--model` string is re-validated with a strict char allowlist (`[A-Za-z0-9._\[\]-]+`, admits `[1m]`) in `terminals.spawn()` before it reaches the shell line; an invalid override falls back to the built-in default and a disabled/invalid slot never spawns. The bootstrap prompt still names the logical slot (so a worker claims `model: opus` tasks) while the terminal launches with the resolved string. Webview selects are data-driven from `WebBoard.models` (enabled ids) + `defaultModel`, replacing the three hardcoded `['default (opus)', 'opus', 'sonnet', 'fable']` lists. Settings surface is VSCode's native `configuration` contribution (per-slot `{enabled, model}` object) — zero new webview, zero deps.
- `loopBoard.models` accepts a per-slot STRING shorthand in addition to the object form (t-c1a7 review feedback): `"haiku": "haiku[1m]"` is sugar for `"haiku": { "model": "haiku[1m]" }` (the common case — just overriding `--model`); the object form is only needed for `enabled: false`. `resolveModels` normalizes a string entry to `{ model }` via `asConfigObject`; the settings schema uses `anyOf: [string, object]` per slot. Users reached for the string form intuitively, so silently ignoring it was a footgun.
- Per-task `rev:` change marker in the index (t-9d5c, builds the t-2a06 concept): an optional monotonic integer on each `.loopboard/TODO.md` entry (grammar v4, fixed order after `groomer:`), so a loop worker reading ONLY the slim index each pass can tell WHICH task(s) changed — including a human edit buried in `tasks/<id>.md` (the original miss on t-5e1a that motivated this). The WRITER (not readers) manages it: `store.ts` computes each touched task's canonical fingerprint BEFORE and AFTER a write — the index block via `serializeEntry` with `rev` excluded (so re-emitting a bumped rev is not itself a "change" → no self-perpetuating bump) plus the `tasks/<id>.md` text — and bumps `rev` iff they differ, on `applyFieldPatch` (index + detail), `promote`; `acceptToDone`/`deleteTask` remove the entry entirely (the "id gone" signal) and `createDraft` adds a new id (the "id new" signal), so neither bumps. Readers NEVER write just to detect a change, so multiple loops (opus/sonnet/haiku) polling constantly never perturb the file or trip each other. Parser tolerates a missing `rev:` (defaults absent/0) and a non-integer value lands in `unknownLines`. Deliberate consequence, accepted by the user as the one slim-index expansion: a DETAIL-file patch now also writes `TODO.md` to persist the bump (the extension's "one file per save" pattern yields here because the whole point is surfacing detail changes in the index). The loop-side "compare each id's rev to last pass" logic is worker behavior documented in LOOP.md Rule 17 / the shipped `media/template-loop.md`, not extension code. `template-todo.md` intro left unchanged (rev is extension-managed, not human-authored; full grammar authority is LOOP.md).
- Review feedback moved from the task file's `## Feedback` section to a repeatable index `feedback:` sub-bullet (t-fbi1), mirroring `note:`: `feedback` is now an `IndexField` (patches `TODO.md`, get/set join/split on `\n` like notes) instead of a `DetailField`, so a loop reading only the slim index (read economy) can see pending Review feedback without opening every task file — and it now participates in `rev:` for free (no new rev logic). `taskfile.ts` stops parsing/writing `## Feedback` entirely; a pre-existing task file with that section keeps it as inert, flagged `unknownLines` content (no migration — human decision, since no live data was at risk and a migration path added complexity for a one-time historical section). The board's Review feedback textarea is unchanged UX-wise; only the storage routing moved.
- Task-file lifecycle (t-6ab4): `store.createDraft` now eager-scaffolds `tasks/<id>.md` at
  creation time (`added: <today>`, built via `parseTaskFile('')` + field-set so it's exactly what
  `serializeTaskFile` already canonicalizes an empty detail to — no fixpoint change), replacing
  the old lazy-create-on-first-write behavior, so a consumer never has to special-case a missing
  file for an ordinary new draft. Deletion needed no change:
  `store.deleteTask` already removed the index entry, `tasks/<id>.md`, and the attachment cache
  dir in one path for drafts and groomed tasks alike (verified by reading, not by a new test —
  `store.ts` imports vscode, so this is manual-F5-only).
- Block-level markdown in card text (t-mkd1): `mdToHtml` (`media/board.js`) is now a line-oriented block pass over the source — ATX headings `#`..`######` → `<h1>`..`<h6>`, unordered (`- `/`* `) and ordered (`1. `) runs → `<ul>`/`<ol>`, everything else = paragraph text with the LEGACY soft-wrap semantics preserved (single `\n` = space, blank line = `<br><br>`, no `<p>` wrapper — plain descriptions render byte-for-byte as before). A new `renderInline(text)` helper (escape → `` `code` `` split → `renderInlineMd`) is reused by headings, list items, and paragraphs so inline bold/italic/code/links work inside every block. The escape-first XSS invariant is intact: the classifier only inspects raw markers, but every user-text fragment is `escapeHtml`'d before it lands in a tag (verified against `<script>`/`<img onerror>`/`- <script>`). Change is global to all three `mdToHtml` consumers (description, done/delivered detail, question text); the question-text container switched `<span>` → `<div class="q-text">` so emitting block tags inside it is valid HTML. New `<hN>`/`<ul>`/`<ol>` CSS is shared across `.desc-rendered`/`.done-detail-text`/`.q-text`, sized down for compact cards. Webview-render-only: no parser/writer/store/grammar changes (board.js isn't in the Docker unit set — safety net is the fixpoint fixtures staying green + manual F5).
- Delivered/Feedback/Note now render as markdown (t-7a94), matching Description: routed all three through the existing hand-rolled `mdToHtml` renderer (`media/board.js`) plus its `a[data-mdlink]` -> `openLink` wiring — Review-card Delivered (dropped the inline-style plain text node for the `.done-detail-text` markdown-CSS class, matching its DONE-archive sibling), DONE-archive Delivered (same one-line fix its neighbouring Description already had), Review feedback, and the Note chip (both keep their leading warning/clock codicon, only the text body is rendered). No renderer change — `mdToHtml` already escapes all text first, so the only practical effect for these short human/worker-authored fields is that staged-attachment `[label](.loopboard/cache/...)` links become clickable and any `` `code` ``/`**bold**`/bare URLs the author typed render formatted, instead of literal. Answers (edit-only textarea) and unparsed lines (verbatim by design) stay out of scope.
- Attachments broadened to any file type, size-capped only (t-058e): removed the host allowlist (`ALLOWED_ATTACHMENT_EXT`, `store.ts`) and the webview image/-MIME pre-filters (drop + paste, all four surfaces) — `readImageFile` renamed `readAttachmentFile`, no longer rejects non-image `File`s; the size cap (`loopBoard.maxAttachmentSizeMB`, unchanged default 10MB) is now the ONLY gate, host-side in `stageAttachment`. No denylist for executables — explicit human decision, overriding the original story text (\"block binaries\"). Wired `wireFieldAttach` (drop + paste) onto the two remaining unwired surfaces, Review feedback and the note-to-worker field, matching the existing description/answer wiring; `controller.ts`'s attach-message field allowlist extended to admit `feedback`/`note` (previously silently fell through to whole-card Description append). Filename sanitization/traversal guards and the size cap are unchanged; no grammar or fixpoint change (links reuse existing description-link rendering).
- Notes-to-worker reskinned to the qa-* visual idiom (t-b149): `renderNote` (`media/board.js`) now emits a `.qa-note` card (yellow left rail, mono uppercase "NOTE" label, edit/delete link actions), a focus-bordered `.qa-note-composer` (+Attach button, "⌘V pastes screenshots · ⌘↵ saves" hint) for the open/editing state, and a dashed `.qa-note-empty` drop-zone for empty — same visual language as t-2394's Q&A panel, all colors/fonts via `var(--vscode-*)`. Scope stays the smallest reskin (human decision): still ONE ephemeral note (`sendPatch('note', …)`, apply-then-delete, Rule 16), no multi-note model, no per-note attachment storage, no index grammar change — attachment chips are derived by scanning the note text for `[name](.loopboard/cache/…)` links (same `extractAttachments` helper the card-level attachments area uses), not a new data model. "Edit" reopens the composer prefilled with the current note text (an update, not a separate mode); unlike the description/answer fields, pasting/dropping into the note composer stages the attachment and inserts its link WITHOUT auto-committing, so more text or attachments can follow before an explicit Save — the New Story composer's pending-attachment pattern, not the field-attach pattern. Wired the note-scoped attach plumbing (human decision, reuse `wireFieldAttach`): `src/controller.ts`'s attach-message field allowlist now admits `'note'`; `src/store.ts`'s `removeAttachment` now also strips a matching link out of `notes[]` (previously only title/description), so the attachment chip's × actually clears the note's link, not just the cached file. `wireFieldAttach` now returns its internal `stage` function so a drop on the empty-state drop-zone (which has no textarea yet) can still stage a file once the composer opens. No thumbnail previews — a real image preview needs a webview-safe URI for an already-staged file (`asWebviewUri` via a new host round-trip), out of scope for this reskin; every attachment renders as a name chip with an extension badge.
- In-tab filter persists across phase tabs and reloads (t-2452): `searchQuery` (`media/board.js`) is now seeded from `vscode.getState()` on load and included in `saveState()`'s persisted blob (same one `phase`/`collapsed`/composer-draft state already uses), and the plain phase-tab `onclick` no longer calls `resetSearch()` — only genuinely new contexts (opening/closing the New Story composer, `revealTask` jumping to a specific task without an explicit search) still clear it, since an old query could otherwise hide the very task being revealed. One shared query across all tabs (human decision — matches the pre-existing single global `searchQuery`, not per-tab state); the `is:unanswered` token persists the same way since it's just part of the query string. The search input's `input` handler now also calls `saveState()` on every keystroke so a mid-typing reload doesn't drop the in-progress filter.
- t-2452 follow-up: the sidebar's phase-count and attention rows (`media/sidebar.js`) post `{type:'reveal', phase}` with no `taskId` and no `search` for a bare phase-only navigation — `revealTask` (`media/board.js`) was still calling `resetSearch()` on that path (its `else` branch fired whenever `search` was absent, regardless of whether a specific task was actually being revealed), silently clearing the filter every time the user switched phases from the sidebar instead of the in-app tab strip. This was the actual remaining persistence gap the human's second and third feedback reports were hitting (an independent Opus subagent review traced it after a concurrent Opus re-groom pass on the task file had instead concluded the PR was simply unmerged — both were partially right: the PR being unmerged also blocked the first fix from reaching any build, and this second, distinct bug was still there underneath). Fix: only call `resetSearch()` when `taskId` is present (a genuine jump to one specific task, e.g. a disk-wins conflict toast's "Review" action) — a bare phase-only reveal now leaves the filter untouched, matching the in-app tab strip's behavior.
- Loop-row reveal desync fixed (t-2e35): `TerminalManager` (`src/terminals.ts`) now clears its cached `revealedModel` flag from a new `vscode.window.onDidChangeActiveTerminal` subscription whenever the active terminal is no longer the one last revealed — so hiding the panel externally (e.g. native CMD+J Toggle Panel, which VS Code observes as no active terminal) no longer leaves the flag stale. Previously a stale flag made the next click on that loop row fire a no-op `closePanel` instead of `show()`ing, requiring two clicks to reopen. This is Option A from the story's implementation choices (a self-healing visibility signal) over Option B (gating the close branch on `activeTerminal` at click time), since Option B would still read the stale terminal as "active" the instant the panel closes and reproduce the same no-op. Change confined to `src/terminals.ts`; the CMD+J-is-native-VS-Code explanation stays documentation-only, no keybinding added. Manual F5 confirmation still pending (headless session).
- Attachment chip idiom unified across every surface (t-f51c): `noteAttachmentChip` generalized into a shared `attachmentChip(item, onRemove, clickable)` (`media/board.js`) — description/draft cards' `renderAttachmentsArea`, the new-story composer's pending list, and notes all render through it now, so `.qa-attachment*` is the single chip look/CSS everywhere (deleted the old ad-hoc inline-styled description/composer lists). `clickable === false` (composer's pending list only, no cache file yet) renders a static `.qa-attachment-name.is-pending` name instead of an `openLink` anchor. Answer and feedback — whose attachment links live inline in the field's own free text rather than a separate store — get a parallel `renderFieldAttachmentsArea(text, commit)` that extracts the same links and, on chip removal, strips the link out of that text and re-commits through the field's normal patch path (`sendPatch`), mirroring the note's edit-and-resave pattern rather than a `detach` host round-trip. Behavioural parity (human decision, not just visual): the note composer's `＋ Attach` file-picker button + `⌘V pastes screenshots` hint were added to the new-story composer, description edits, answer edits, and the Review feedback composer — all four already supported silent drag-drop/paste (t-058e/t-att1); this only makes attaching discoverable without a keybinding, same as before, no new host round-trip. Real image thumbnails stayed explicitly out of scope (confirmed unchanged from t-b149's decision).
- New Story composer gains a save keyboard shortcut (t-9b50): the composer `area` textarea now binds a `keydown` listener wiring `isSaveShortcut` (Cmd/Ctrl+S, the existing convention every other editable field already uses) to `commitDraft()`. No new validity check needed — `commitDraft` already no-ops on an empty/whitespace-only composer, so the shortcut is silently inert exactly like the disabled Save Draft button. Scope stayed composer-only (per-card fields already have their own Cmd/Ctrl+S bindings). Review feedback reversed the initial "both Cmd/Ctrl+S and Cmd/Ctrl+Enter" answer — the human called the Cmd/Ctrl+Enter half a mistake on their own accepted answer and asked for Cmd/Ctrl+S only, so the Enter branch was removed.
- Depends-on chips filter instead of jump, for every target (t-a524): added a reserved `task:<id>` token to `matchesQuery` (`media/board.js`, exact case-insensitive id match, ANDs with other tokens like `is:unanswered`). The depends-on chip's `onclick` now routes through `revealTask(dep.id, phase, false, 'task:' + dep.id)` instead of jumping/scrolling, for BOTH Done and active targets — human decision widened the original Done-only scope ("Make it consistent. Do it for ALL stories in all Phases"). A `dep.met` (Done) target skips the `board.phases` existence scan entirely and routes straight to the Done tab, since `dep.met` already reflects `doneIds.has(id)` (`src/view.ts`) independent of the truncated 50-entry `phases.done` window — so an old Done dependency outside that window still resolves correctly instead of a false "not found". A non-Done target still scans `board.phases` for its live phase (unchanged "not found" toast if absent anywhere). Chip tooltip/aria-label changed from "Go to <id>" to "Filter to <id>" to match the new universal behavior.
- Composer attachment size cap enforced at attach time (t-5f50): `WebBoard.maxAttachmentSizeMB` (`src/view.ts`, set in `controller.ts`'s `buildWebBoard`) surfaces the configured cap to the webview so the New Story composer's `addPendingAttachment` (`media/board.js`) can reject an oversized file against `file.size` BEFORE staging it — same "Attachment is too large (max NMB)." message as every existing-card surface, no pending-list entry, no `loopboard-pending:<n>` placeholder inserted. Previously the composer only round-tripped bytes to the host at Save Draft, so the cap silently didn't apply until then.
